# Contributing to JKY Terminal

Thanks for wanting to help build the world's best AI terminal — for everyone.

## Ground rules

- Read [`ROADMAP.md`](./ROADMAP.md) first. It defines the current phase, tech stack, and architecture — please build with the grain of it rather than against it.
- One GitHub Issue per task. If you're picking up a roadmap checklist item that has no issue yet, open one and link it to the relevant phase milestone before starting work.
- Small, focused PRs. Prefer several small PRs over one large one.

## Branch & commit conventions

- Branch names: `feat/<short-description>`, `fix/<short-description>`, `docs/<short-description>`, `chore/<short-description>`.
- Commits follow [Conventional Commits](https://www.conventionalcommits.org/) (`feat:`, `fix:`, `docs:`, `chore:`, `test:`, `refactor:`).

## Local setup

Full setup instructions land in Phase 1 (monorepo scaffold) — this section will be filled in as soon as `apps/desktop` exists. In the meantime, discuss setup/tooling questions in GitHub Discussions.

## Pull requests

- Include tests for behavior changes.
- Update relevant docs in `docs/` and, if the change affects a roadmap item, check off the corresponding box in `ROADMAP.md` in the same PR.
- Every merged PR gets full GitHub contributor credit — no CLA required.

## Security issues

Please do **not** open a public issue for a security vulnerability. See `SECURITY.md` (added in Phase 9) for the responsible-disclosure process.

## Code of Conduct

This project follows the [Contributor Covenant](./CODE_OF_CONDUCT.md) (added in Phase 15). Be respectful, be constructive.
